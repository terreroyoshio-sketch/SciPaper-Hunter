# Design MD Collection — Prompt Templates

---

## Template 1: 选择合适设计风格

```
请使用 design-md-collection。我的产品是【产品类型】，
目标用户是【用户群体】，页面类型是【官网/后台/文档站/支付页/仪表盘】，
我希望整体感觉是【关键词】。
请从 DESIGN.md 索引中推荐 3 种适合的风格方向，说明选择理由、
适合点、不适合点和品牌风险。不要直接复制品牌资产。
```

## Template 2: 参考 Stripe 风格做支付页

```
请使用 design-md-collection。请参考 Stripe 的设计方法，
而不是复制 Stripe 品牌资产，为我的【产品名称】设计一个支付页面。
请输出信息架构、视觉层级、表单布局、信任元素、错误状态、CTA 设计、
移动端适配和 Tailwind 实现建议。
不要使用 Stripe logo、商标、专有插图或原文案。
```

## Template 3: 参考 Linear 风格做后台

```
请使用 design-md-collection。请参考 Linear App 的效率感和
信息组织方式，为我的【系统名称】设计一个项目管理后台。
请重点处理侧边栏、列表、筛选器、任务状态、详情面板、快捷操作和空状态。
输出 DESIGN.md 草稿和 React/Tailwind 组件结构。
```

## Template 4: 参考 Vercel/Supabase 做开发者工具官网

```
请使用 design-md-collection 和 Frontend Design。我的产品是
【AI Agent/API 服务/开源框架/数据工具】。请选择 Vercel、Supabase、
Cursor、Claude 或 Mintlify 中最合适的一种或两种作为风格启发，
生成官网首页结构、视觉系统、hero 区、功能区、代码展示区、价格区、
FAQ 和 CTA。不要复制任何品牌资产。
```

## Template 5: 参考 Mintlify 做文档站

```
请使用 design-md-collection。请参考 Mintlify 的开发者文档信息架构，
为我的【项目名称】设计文档首页和文档布局。
请输出导航结构、搜索入口、代码示例区、卡片布局、版本切换、
API reference 入口和移动端适配方案。
```

## Template 6: 无指定风格自动选型

```
请使用 design-md-collection。我的产品是【产品描述】。
我不知道该参考哪种风格。请根据产品类型、目标用户和使用场景
自动推荐 3 套设计系统方向，并给出最终推荐。
请说明每种方向会影响颜色、字体、组件密度、页面节奏和用户感受。
```

## Template 7: 生成项目 DESIGN.md

```
请使用 design-md-collection。请基于以下产品定位和参考风格，
为我的项目生成 DESIGN.md。内容包括品牌气质、颜色系统、字体层级、
间距规则、圆角阴影、按钮、卡片、表单、导航、图标、图表、空状态、
错误状态、响应式布局和禁用规则。
```

## Template 8: 将已有页面重构为产品级 UI

```
请使用 design-md-collection、Frontend Design 和 refactor。
以下是我的现有页面代码。请先诊断 UI 问题，再基于合适的
DESIGN.md 风格重构。不要改变业务逻辑。输出修改计划、
组件拆分、样式规则和最终代码。
```

## Template 9: 科研项目展示页

```
请使用 design-md-collection、nature-figure、scientific-visualization
和 ppt-master。请为我的科研项目【项目名称】设计一个展示型网页或
PPT 页面，风格参考【Vercel/Linear/Apple/Mintlify】的设计方法。
要求浅色系、信息层级清晰、图表专业、避免 AI 味和营销空话。
```

## Template 10: 品牌风险审查

```
请使用 design-md-collection。请检查以下 UI 方案是否存在过度模仿
某品牌的风险。重点检查 logo、颜色、图标、插图、布局、文案和组件
是否可能被误认为原品牌。输出修改建议，使其成为 brand-inspired
而不是 brand-cloned。
```
