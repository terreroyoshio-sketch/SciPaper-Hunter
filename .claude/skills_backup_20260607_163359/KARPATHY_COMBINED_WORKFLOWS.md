# Karpathy Guidelines — 与已有 Skills 组合工作流

---

## A. 软件开发与调试工作流

```
1. using-superpowers
   明确任务目标、边界、验收标准。

2. karpathy-guidelines
   执行先思考、简单优先、精确改动、目标驱动。

3. Playwright
   用于浏览器自动化测试。

4. Mano-CUA
   只在必须操作桌面 GUI 时使用，并加风险分级。

5. skill-creator
   将重复调试流程封装成 skill。
```

---

## B. 科研代码复现工作流

```
1. markitdown
   解析论文、README 和实验说明。

2. keyword-literature-download
   下载和整理相关文献。

3. karpathy-guidelines
   制定最小复现路径。

4. nature-figure
   复现实验图或生成审稿级图件。

5. word-document-processor
   整理复现报告或 Word 文档。
```

---

## C. 论文申报书工具开发工作流

```
1. nsfc-proposal-architecture-pipeline
   明确项目研究目标和研究内容。

2. objective-innovation-auditor-pipeline
   审计工具是否真的服务于创新点。

3. karpathy-guidelines
   控制代码实现复杂度，避免无关功能扩张。

4. terminology-coherence-editor
   统一工具说明中的术语。
```

---

## D. 提示词生成工作流

```
1. using-superpowers
   明确任务目标。

2. brainstorming
   生成方案。

3. karpathy-guidelines
   把方案转成可执行、可验证的 Claude Code 提示词。

4. reviewer-red-team-auditor
   压力测试提示词中的风险和歧义。
```

---

## E. 代码审查与重构工作流

```
1. karpathy-guidelines
   先确认是否有必要重构，最小改动原则。

2. surface-innovation-auditor
   驳回表面改进（如有）。

3. verification-before-completion
   重构前后确保测试通过。
```

---

## F. 论文全流程写作 + 代码实现

```
1. using-superpowers
   明确任务边界

2. critical-literature-review-pipeline
   生成综述逻辑

3. objective-innovation-auditor-pipeline
   审计创新点

4. karpathy-guidelines
   按最小工程原则实现代码

5. nature-figure
   绘制图件

6. word-document-processor
   Word 成稿
```
