# Addy Osmani Agent Skills — Combined Workflows

---

## A. 新功能开发工作流

```
1. Using-Superpowers → 明确任务目标、边界和验收标准
2. grill-me → 拷问模糊需求
3. /spec → 写工程规格
4. /plan → 拆成小步任务
5. tdd / testing → 定义测试优先策略
6. /build → 逐步实现
7. /test → 运行或规划测试
8. /review → 代码审查
9. /code-simplify → 去除不必要复杂度
10. /ship → 上线前 go/no-go，不自动部署
```

## B. Bug 修复工作流

```
1. diagnose → 复现问题，最小化问题
2. /spec → 定义 bug 行为、预期行为和验收标准
3. /plan → 规划修复路径
4. tdd → 补回归测试
5. /build → 最小修复
6. /test → 验证修复
7. /review → 审查回归风险
```

## C. 重构工作流

```
1. zoom-out → 理解系统位置
2. improve-codebase-architecture → 识别架构问题
3. /spec → 定义重构目标和非目标
4. /plan → 分阶段重构
5. /build → 小步重构
6. /test → 保证行为不变
7. /code-simplify → 删除多余复杂度
```

## D. Web App 工作流

```
1. agent-browser → 探索页面行为
2. Playwright / webapp-testing → 建立端到端测试
3. /spec → 明确功能规格
4. /build → 实现
5. /test → 自动化验证
6. /ship → 上线前审查
```

## E. 科研软件和项目申报工具工作流

```
1. nsfc-proposal-architecture-pipeline → 明确科研项目目标
2. objective-innovation-auditor-pipeline → 审查功能是否真实有价值
3. /spec → 转成软件规格
4. /plan → 拆成开发任务
5. /build → 实现原型
6. /test → 验证功能
7. /review → 审查可维护性
8. docs → 生成使用说明
```

## F. 安全上线工作流

```
1. /review → 代码审查
2. test-engineer → 测试审查
3. security-auditor → 安全审查
4. git-workflow → 生成变更说明
5. /ship → go/no-go 决策
```
