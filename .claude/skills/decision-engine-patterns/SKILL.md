# Decision Engine Patterns

## 核心原则

先问一个问题：**这个动作真的需要"生成"吗？** 路由、分派、分类、筛选、打分、是否类判断 —— 这类决策的输出是**类型化结构**（选哪个 / 打几分 / 是或否），不是自由文本。对这类任务，非自回归决策引擎（单次前向直接出决策）在成本、延迟、可靠性三方面都可能优于"LLM 生成 → 解析"的常规做法。

- **决策与生成分离**：决策引擎只做"选什么"，不做"写什么"；需要文本时，只在必要时调用小模型生成。来源生态的原文表述见 references。
- **输出即数据，永不即可执行物**：任何决策输出在执行前必须经过确定性校验层。这是权限问题，不是质量问题。

## 何时使用

- 设计新的路由 / 分派 / 门禁 / 筛选机制
- 审查现有方案：解析脆弱、调用成本高、低置信度硬猜、大批量吞吐低
- 评估"要不要把某类 LLM 决策换成决策引擎"

不用：需要生成文本或解释的场合；选项空间开放、无法枚举的场合；需要多步推理链的场合；低频一次性决策（直接用 LLM 更简单）。配套：工作台路由与 skill 分发见 `research-master-router`；执行可靠性见 `agent-execution-patterns`。

## 十条模式速查

| # | 模式 | 一句话 | 典型反模式 |
|---|------|--------|-----------|
| 1 | 决策/生成分离 | 选择类用决策引擎，文本类才用 LLM | 所有事情都让一个大模型生成 |
| 2 | 类型化输出 | 输出 = 选项/分数/概率，消灭解析层 | 让模型输出 JSON 再祈祷解析成功 |
| 3 | 动作空间枚举化 | 动作与目标都是编号枚举，未定义动作不可达 | 模型可自由输出任意工具名/参数 |
| 4 | 一次往返多决策 | 单请求返回动作 + 多个候选槽位 | 每问一个小问题打一次网络往返 |
| 5 | 置信度→人审升级 | 低置信度不硬猜，升级给人审 | 阈值以下照样自动执行 |
| 6 | 输出永不即可执行物 | 决策经确定性校验层才落地 | 模型输出直接当选择器/命令执行 |
| 7 | 边界显式 + 失败终态 | 明确排除的场景写进文档；BLOCKED 是合法终态 | 边界靠默认值猜；失败静默卡住 |
| 8 | 对比口径纪律 | 同任务、重复次数、中位数；单例演示≠基准 | 单跑一次 7.1s 当性能结论 |
| 9 | 单前向 + 批量吞吐 | 无生成即无解析；批量同题摊薄成本 | 大批量筛选逐条跑生成式模型 |
| 10 | 托管 vs 开源形态 | 先问托管还是自托管；线协议兼容可降切换成本 | 绑死单一闭源 API 无退路 |

## 模式详解

每条按"机制 → 失败信号 → 本工作台应用"展开。

1. **决策/生成分离**：来源生态的分工 —— 决策引擎"picks an operation and an element"，文本由"a small LLM writes text only when the operation is TYPE_TEXT"。生成只在真正需要字符串时发生。
   失败信号：用一个大模型同时干路由和写作；决策调用也在付生成价格。
   应用：把工作台里"选 route / 选 skill / 判 pass-fail"的环节与"写正文"环节拆开评估；前者是决策引擎候选。

2. **类型化输出**：输出是三种类型化决策 —— `choice`（选哪个）、`score`（打分）、`noul`（yes/no 概率），跨 100+ 语言，单次前向完成，"没有任何待解析的输出"。
   失败信号：解析层是最大故障源（模型偶尔输出多余文字、格式漂移）；需要重试与容错代码。
   应用：门禁/分流若现在靠"让 LLM 输出 JSON 再 parse"，换成类型化决策输出可直接删掉解析层。

3. **动作空间枚举化**：动态索引动作空间 —— 元素表带编号行（`[1] button`、`[2] combobox`），固定操作集（CLICK / TYPE_TEXT / SELECT / SCROLL_UP / SCROLL_DOWN / WAIT / DONE / BLOCKED）；"Only supported operations and targets are offered"。
   失败信号：模型幻觉出不存在的工具/参数；执行端要防御任意输入。
   应用：skill 路由、工具选择的候选项做成编号枚举再决策；不在枚举内的动作理应不可达。

4. **一次往返多决策**：单个请求返回操作 + 各目标槽（`click_target` / `type_text_target` / `select_target`），目标槽是投机性的——只有被选中操作对应的槽会被执行。原文称之为 "Two decisions, one network round trip"。
   失败信号：一个决策周期打多次 API，延迟叠加；成本随往返次数线性增长。
   应用：批量决策合并进一次调用；无关槽位在执行层丢弃。

5. **置信度→人审升级**：官方用例范式 —— "routing incoming support tickets by department, **with human review for uncertain decisions**"；输出含概率/分数，低置信度分流给人工。
   失败信号：低置信度自动执行；或全量人工（丢失自动化收益）。
   应用：与本工作台 Human Gate / NEED_USER_APPROVAL 机制对齐：决策引擎给分数，阈值以下升级给人，而不是硬猜。

6. **输出永不即可执行物**：安全纪律原文 —— 每个目标从**观测到的节点**解析；执行器复核新鲜度（freshness）与点击遮挡；模型输出 "never becomes selectors, coordinates, shell commands, or executable JavaScript"。
   失败信号：模型输出直接进 DOM 选择器 / shell / 代码执行路径；无二次校验。
   应用：任何决策输出在执行前经确定性校验（对照最新状态、范围检查、过期检查）——与本工作台"判定权只在确定性模块"的既有原则同构。

7. **边界显式 + 失败终态**：来源项目声明式划界（shadow roots、frames、canvas、上传、弹窗、嵌套滚动明确排除在 MVP 之外）；失败是枚举终态之一（BLOCKED），不是沉默。
   失败信号：边界靠口口相传；失败表现为静默卡死或模糊报错。
   应用：新机制上线先写边界声明（不下"全能"结论）；失败路径显式化为合法终态（对应反造假：能力边界如实汇报）。

8. **对比口径纪律**：来源自述的分层 —— ① 同任务对比（6 次交替运行：中位任务时长 9.450s → 7.092s，-25%；浏览器协议调用中位数 1,092 → 101）；② 单例演示（单跑 7.1s）；③ 自我警告（"three repeats of one task on one browser profile, not a general reliability benchmark"）。三层不可混用。
   失败信号：把单例演示当基准；把他方自报数字当独立复测结论。
   应用：任何决策引擎/路由的性能对比先定口径（同任务、同环境、重复次数、中位数 vs 单例）；本工作台计分是"每源平均"这类口径陷阱已有前车之鉴。

9. **单前向 + 批量吞吐**：决策引擎不做文本生成（无 token 逐位解码、无输出解析）；自述性能：单问 33ms、T4 批量 7.2ms/题；训练用 RLCD（对着严格 proper scoring rules 做 RL）。
   失败信号：大批量分类/筛选逐条跑生成式模型，成本与延迟随条数线性堆积。
   应用：文献初筛、引用初分类、批审分流等"大 N 小决策"场景是决策引擎的优势区。

10. **托管 vs 开源形态**：托管闭源（TypeSafe 的 System One / 第三方称 Jev，线协议 `POST /v1/systemone`，第三方转述 236–276ms p50、$0.042/1M tokens）vs 开源实现（laya Apache-2.0：Router + ModernBERT 系底座，多语言，可自托管；社区另有 MLX 运行时、Claude Code 压缩插件、可自训练变体）。协议复用策略：laya 复用 Jev 线协议，客户端"只需换个 base URL"。
    失败信号：绑死单一闭源 API；迁移成本无人评估。
    应用：评估时先问"托管还是自托管"；若走托管，确认线协议是否有开源兼容实现作退路。

## 审查清单

审查一个路由/决策方案时逐条验证：

- [ ] 这个决策真的需要生成式 LLM 吗？（选项可枚举 + 输出是选择/分数 → 决策引擎候选）
- [ ] 决策输出是类型化结构（无自由文本解析层）？
- [ ] 动作/目标都在枚举集合内？未定义动作不可达？
- [ ] 低置信度有升级通道（人审/保守回退），而非硬猜？
- [ ] 决策输出在执行前经过确定性校验（对照最新状态、范围/过期检查）？
- [ ] 失败有显式终态（BLOCKED 类），不会静默卡住？
- [ ] 性能对比口径明确（同任务、重复次数、中位数 vs 单例；自述 vs 独立复测分开写）？
- [ ] 托管还是自托管已决策？线协议是否有兼容实现作退路？
- [ ] 适用边界（不支持的输入形态/场景）已写清？
