# Completion Guard Patterns

## 核心原则

**"完成"必须是一个可运行的事实，不是一个说法。** 验收条件写进文件、证据绑定到定义、放弃有显式终态——三件事缺一，完成声明就退化为散文。来源项目原文证据见 references。

- **守卫的最小性**：每条防御必须能触发三者之一——**拒绝、恢复、诊断**。做不到这三件事之一的"防御"（没人读的校验和、为想象未来造的兼容层）是负担，不是保护。
- **拦截的证据分离**："我们拦了"与"宿主真的执行了拦截"是两条独立事实，分开记录、分开陈述。

## 何时使用

- 设计任务/流水线的验收与完成机制
- 审查"agent 说完成了"的可信度
- 排查：完成声明无据、检查形同虚设、评审越权改文件、范围膨胀、重复劳动、拦截未生效

不用：一次性脚本、无验收可言的主观任务。配套：执行可靠性见 `agent-execution-patterns`；结果级证据治理见 `research-execution-provenance`。

## 十条模式速查

| # | 模式 | 一句话 | 典型反模式 |
|---|------|--------|-----------|
| 1 | 可运行验收台账 | 先写 GATES.md；通过 = 退出码 0 且输出匹配 EXPECT | 验收条件只在对话文字里 |
| 2 | 证据绑定定义 | 证据绑定到定义文本的哈希；定义改了证据即失效 | 一次性快照冒充持续证据 |
| 3 | 重验证通道 | `--reverify` 重跑全部（含已完成）；`--status` 只读不执行 | 验过就永不再验 |
| 4 | 放弃即交接 | 放弃 gate = HANDOFF，退出非零，父项不可标完成 | 悄悄跳过，父项照常完成 |
| 5 | 无进展熔断 | 循环有硬上限；连续无实质进展自动放行 | 无限重试/无限纠错 |
| 6 | 范围守恒 | 只动被要求的东西；无现用途的扩展停下 | 修一个 bug 顺手重构三个模块 |
| 7 | 防御最小化 | 每条防御能触发拒绝/恢复/诊断之一 | 无人读的校验和；想象未来的兼容层 |
| 8 | 意图守恒 | 只读就只读；修改需要授权 | 评审模式下改了文件 |
| 9 | 免重复劳动 | 无新问题不重读/重测/重审 | 复读复测复审凑工作量 |
| 10 | 拦截证据分离 | 拦了 ≠ 宿主执行了；守卫有 OBSERVING→ARMED 状态机 | 把"我们拒绝了"写成"它没发生" |

## 模式详解

每条按"机制 → 失败信号 → 本工作台应用"展开。

1. **可运行验收台账**：先写 `GATES.md`（或等价台账），每条 gate = `CHECK:`（命令）+ `EXPECT:`（期望输出）+ `CWD:` + `EVIDENCE:`；**可运行 gate 通过 = 退出码 0 且 EXPECT 匹配**。解析器拒绝空台账、重复 id、不完整 gate。
   失败信号："已完成"靠嘴说；验收条件散在对话里，无法复跑。
   应用：把每项交付的验收写成可运行命令 + 期望输出；台账进仓库随任务归档。

2. **证据绑定定义**：自动证据绑定到解析后的 CHECK/EXPECT/CWD 定义的 SHA-256；**定义变了 → 证据自动 stale**（fail closed）。来源明确声明：这检测"漂移"，**不检测"篡改"**——限定必须一起说。
   失败信号：检查逻辑改过了，旧证据还挂着装门面。
   应用：批量任务的检查脚本改动后，历史证据自动失效需重跑——防止"证据还在但已不适用"。

3. **重验证通道**：`--reverify` 重跑全部 gate（含已标记完成的）；`--status` 只报告不执行；正常模式在执行未批准命令前披露已解析的命令/环境。
   失败信号：验过即封存；环境变了无法快速全量复核。
   应用：交付前/冻结前跑一次全量重验证；日常用只读状态查询。

4. **放弃即交接**：放弃一条 gate 产生 `HANDOFF REQUIRED` 终态，退出码 1，且**不能把父项标记完成**——放弃是显式且传染的。
   失败信号：跳过/放弃静默进行；上层照常标完成。
   应用：任何未通过的检查项要么修复、要么显式交接，不允许"绕过继续"。

5. **无进展熔断**：可选 Stop hook 在 gate 未达标时返回 block；**连续 6 次无实质进展自动放行**（防死循环）。对应既有教训（DOT-2：修状态判定，不调大轮询间隔）。
   失败信号：纠错循环无上限；同一问题第 N 轮还在原地。
   应用：评审-修正循环设声明上限；达到上限 → 升级给人或交接（与 provenance 参考 `artifact-and-review-evidence` 的"有界修正循环"配套）。

6. **范围守恒（SHIT-S）**：修复一个问题時只动相关问题；**扩展没有现用途的 → 停**。
   失败信号：修 A 改了 B/C；顺手重构建。
   应用：对应 ADDY 原则 #4（一次一个垂直切片）；审 diff 时按"被要求的范围"核对。

7. **防御最小化（SHIT-H）**：没人读的校验和、为想象未来造的兼容层都是负担；**防御必须能触发拒绝、恢复或诊断**，否则删掉。
   失败信号：防御代码堆积但都不带动作语义。
   应用：加任何"防御性"代码前问：它触发哪一条？——与"不加未要求的哈希/校验和"纪律一致。

8. **意图守恒（SHIT-I）**：review 模式 = 只报告问题；**修改需要授权**（"审查就报告问题，修改需要授权"）。
   失败信号：只读评审改文件；monitor 模式动了产物。
   应用：子代理/评审角色的默认权限收窄为只读；写操作显式授权。

9. **免重复劳动（SHIT-T）**：没有新问题、没有新变更时，不重复读/测/审——重复本身要有依据。
   失败信号：同一文件反复读、同一测试反复跑、同一内容反复审。
   应用：重跑前先问"自上次以来变了什么"；无变化的重跑只允许在冻结/交付门禁处（对照模式 3）。

10. **拦截证据分离**：被拒时报告 `permission_deny_returned`，而**宿主是否真的执行了拦截单独记录为 `hostEffect: unobserved`**（未观察≠未发生，也≠已发生）；守卫安装后为 `OBSERVING / unconfirmed`，需显式指令才 `ARMED`；watch 模式保持只观察。
    失败信号：把"我们发出了拒绝"写成"它被阻止了"。
    应用：任何拦截/门禁的证据必须分两栏："策略发出"与"实际效果"——与证据等级纪律一致（CONFIGURED ≠ RUNTIME_VERIFIED）。

## 审查清单

审查一个完成/守卫机制时逐条验证：

- [ ] 完成定义是**可运行**的吗（命令 + 期望输出），而非文字描述？
- [ ] 证据绑定到定义本身（改动即失效），而非一次性快照？
- [ ] 有重验证通道（全量重跑 + 只读状态）？
- [ ] 放弃/跳过有显式终态，且阻断父项完成？
- [ ] 循环（重试/纠错）有硬上限与无进展熔断？
- [ ] 只动被要求的范围？无现用途的扩展被拒绝？
- [ ] 每条防御能触发 拒绝/恢复/诊断 之一？
- [ ] 只读模式真的只读？修改需要显式授权？
- [ ] 无新问题的重复工作被去重？
- [ ] 拦截报告分离"策略发出"与"实际效果"？守卫有 OBSERVING→ARMED 状态机？
