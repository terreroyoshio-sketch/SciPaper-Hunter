# Agent Execution Patterns

## 核心原则

不假设 agent 会听话、会活着、会只跑一次。每个机制回答同一个问题：**如果这步失败 / 重复 / 消失，系统怎么知道、怎么修？**

- **意图与执行分离**：执行意图持久化（DB / 文件），进程只是短暂执行窗口；进程死了，意图还在，可被重建。
- **终态三选一不变量**（原文出处见 references）：任何"已指派且未关闭"的任务，必须满足其一 —— ① 有活的执行路径；② 有持久的等待理由（审批 / 依赖 / 监控）；③ 有明确的终态或阻塞处置。三者皆无 = 系统性 bug，不是运气不好。

## 何时使用

- 设计新的多 agent / 多步流水线
- 审查现有编排的执行可靠性
- 事故排查：丢任务、重复跑、卡死、成本异常、配置不生效

不用：单次脚本、一次性任务、纯人工流程。

配套：组织级流程治理见 `ai-native-workflow-governance`；子代理协作纪律见 `subagent-collaboration-governance`。本 skill 只管执行可靠性模式。

## 十条模式速查

| # | 模式 | 一句话 | 典型反模式 |
|---|------|--------|-----------|
| 1 | 心跳执行 | 有限执行窗口，唤醒即跑、写完终态即退 | 常驻进程挂着等事件 |
| 2 | 唤醒合并 | 运行中收到新唤醒 → 合并计数，不重复起跑 | 一个事件起一个 run |
| 3 | 原子领取 | 领任务 = 事务；被占 = 让路，永不重试抢锁 | 两个 agent 抢同一产物 |
| 4 | 持久续跑 + 孤儿对账 | 续跑意图入库；定期扫描孤立任务补唤醒 | 靠内存定时器 / 人盯 |
| 5 | 幂等 = 存储层约束 | 幂等键 + 唯一约束，重投由存储拒绝 | "代码里判断过了" |
| 6 | 配置指纹 | 配置类目哈希入会话，变了就重置 | 改了配置假设已生效 |
| 7 | 进程身份 + 输出监护 | 用 boot-id 而非 PID；静默分级告警 | 用 PID 判活；挂死无人知 |
| 8 | 预算门 + 重试守恒 | 调用前查预算；重试是守恒资源 | 多路恢复各给一份重试 |
| 9 | 协议即清单 | agent 职责 = 清单文档 + run-id 归因 | 提示词里散描述 |
| 10 | 工程纪律 | 每个失败模式一个测试 / 检查脚本 | 失败处理靠自觉 |

## 模式详解

每条按"机制 → 失败信号 → 本工作台应用"展开。

1. **心跳执行**：有限执行窗口，四种唤醒源（定时 / 指派 / 手动 / 自动化），跑完写终态即退出；空闲 = 零进程。
   失败信号：长驻进程挂着等事件；重启即丢全部状态。
   应用：长链路任务（多步审稿、跑批、流水线）写成"持久意图 + 唤醒条件"，而不是挂着等。

2. **唤醒合并**：运行中收到新唤醒 → 合并入下一次并计数（coalesced），不重复起跑；调度器在特定状态下拒绝开工（部署 drain 中、数据恢复中等）。
   失败信号：一个事件起一个 run；同一任务并发多跑。
   应用：多 agent 重复触发同一任务时先合并再排程，省 token。

3. **原子领取 + "409 永不重试"**：领任务 = 原子事务 + 执行锁；被占用 → 换任务干，永不重试抢锁；跨团队任务不取消、只转交。
   失败信号：两个 agent 同时写同一文件 / 数据集。
   应用：共享产物的写入权 = 一写者一锁，冲突让路。

4. **持久续跑 + 孤儿对账**：续跑意图入库（带类型 + 幂等键），不靠内存定时器；启动时与周期 tick 扫描"孤儿任务"（已指派、开着、无活路径、无等待理由）补一条唤醒。不变量写进系统而不是文档。
   失败信号：任务停在中途无人接手；或相反 —— 状态不收敛导致无限补跑（见反面教材）。
   应用：给 runs/EXP-* 和多步流水线加"孤立任务扫描"；把三选一不变量写进验收条件。

5. **幂等 = 存储层约束**：幂等键 + 按前缀作用域的部分唯一索引（带状态谓词：失败 / 跳过不占位，允许重投）；重投由数据库拒绝，而非代码自觉。
   失败信号："我们代码里判断过了"；重试产生重复记录。
   应用：EXP 编号、handoff_id、引用审计（只追加不覆盖）都能升级为约束级幂等。

6. **配置指纹**：会话里存配置类目的指纹（模型 / 工作区 / 指令等，见 references），任一变化 → 重置会话或重建工作区；"生效"是被证明的，不是被假设的。
   失败信号：改了配置假设已生效；缓存陈旧导致行为漂移。
   应用：config_effective 类机制用指纹比对替代"改过就是生效"——专治假生效。

7. **进程身份 + 输出监护**：进程身份用 boot-id + 租约过期（"PID 跨容器不是身份"）；输出静默分级（not_applicable / ok / suspicious / critical / snoozed）自动告警；服务器重启"收养"在跑的 run；发布前先 drain。
   失败信号：用 PID 判活；长任务静默挂死无人知。
   应用：长跑批（MATLAB / Python）用 session 标识判活；加输出静默分级告警。

8. **预算门 + 重试预算守恒**：调用前查预算（按作用域，见 references），超限拦截并记录"被跳过"原因；重试是守恒资源 —— 进程丢失、修复恢复都不新开预算池；超限取消待办唤醒。
   失败信号：多路恢复各给一份重试；成本无人拦。
   应用：token-saver 场景：调用前检查 + 重试计数守恒。

9. **协议即清单**：agent 侧标准程序写成清单文档（身份 → 审批 → 领任务 → 干活 → 汇报）；所有写操作带 run-id 强制归因；恢复补跑标注为 "a liveness repair, not evidence that the previous model requested another turn"——恢复动作与模型意图分开记录。
   失败信号：提示词散描述；写操作无法归因到具体运行。
   应用：每个 agent 的职责落成一份清单式 skill；写操作带运行标识。

10. **工程纪律**：每个失败模式一个独立测试（僵尸、孤儿租约、重唤醒节流各有专属测试）；CI 检查脚本化（禁推 / 令牌门 / 模块边界）；视觉变化用快照基线证明"零变化"。
    失败信号：失败处理靠自觉；检查靠人肉。
    应用：把自己项目的每个失败案例固化为回归测试或审查清单。

## 反面教材：DOT-2 循环

"成功但不收敛"：run 报告完成，但结果契约未收敛 → 状态保持进行中 → 对账器每 30 秒补一条唤醒 → 重复输出同一答案。
教训：**修状态判定，不要调大轮询间隔**（原文 "increasing the polling interval only hides the bug"，译：提高轮询间隔只会掩盖 bug）。诊断时对比：唤醒原因、重试链、终态判定、是否真有持久等待路径。

## 审查清单

审查一个多 agent / 长任务系统时逐条验证：

- [ ] 每个"已指派未关闭"任务，三选一不变量成立？（活路径 / 等待理由 / 明确终态）
- [ ] 运行中的重复唤醒会合并，而不是并发起跑？
- [ ] 任务领取是原子的？冲突方让路且不重试？
- [ ] 重投递 / 重试由存储层幂等约束拒绝？
- [ ] 配置变更能证明"已生效"（指纹 / 版本比对）？
- [ ] 进程判活用身份标识而非 PID？有输出静默告警？
- [ ] 预算在调用前检查？重试次数守恒？
- [ ] 每个已知失败模式有对应测试或检查脚本？
